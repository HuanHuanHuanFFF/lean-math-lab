# 仓库结构与多任务工作方式

本仓库同时保存可复用的 Lean 库和研究过程。已发布的 `Math.A071999` 路径与定理名称保持稳定；本轮通过索引和工作入口整理材料，避免打断既有引用。

| 位置 | 存放内容 | 使用约定 |
|---|---|---|
| `Math/`、`Math.lean` | 已接受的定义、引理、定理和库入口 | 新模块导入库入口；新领域按主题建子目录；已发布路径保留兼容入口 |
| `Tests/` | 题面对照、边界及公理审计 | 按结果命名，完成结果应有可失败的公理断言 |
| `Examples/` | 面向使用者的最小调用示例 | 只用公开接口；由统一验证入口自动发现 |
| `research/README.md` | 正式任务索引 | 区分候选、进行中、暂停和闭合 |
| `research/tasks/<编号>-<简称>/` | 单个任务的目标、尝试、证据及下一步 | 从模板建立入口；大型搜索记录和报告按需另存 |
| `.agents/skills/lean-research/` | 可重复使用的研究工作流和任务模板 | 随仓库携带，无需在 C 盘安装全局副本 |
| `scripts/verify.ps1` | 统一验证入口 | 构建库，并逐个检查 `Math/`、`Tests/`、`Examples/` 中所有 Lean 文件 |
| `.tools/`、`.lake/` | 本地工具、实验和依赖缓存 | 不发布；本机的新工具及缓存继续留在 D 盘 |

## 每个任务如何推进

选择候选后建立任务记录，先写准确题目、已知状态及下一阶段的检查点。探索中持续记录最后证明的内容、失败的路线和待解决点。未完成的实验留在任务目录或 `.tools/`，不放进会被统一验证的三个目录。

多轮开放问题维护任务内的 `frontier.md`，作为接续前先读的全局缺口图：链接已有证据，指出尚未覆盖的参数和下一个会改变路线选择的检查。具体规则见 [Lean 研究工作流](../.agents/skills/lean-research/SKILL.md)；新任务模板也可直接内嵌这一小节。

研究阶段、Lean 证明状态、审阅方式、新颖性与公开状态分别记录。例如“已公开”不等于“有数学创新”，“AI 审查通过”不等于“人类同行评审”。已知结果的形式化也可以是完整成果。

并行任务各自认领记录和代码文件。共享入口、依赖升级、通用引理及发布由主任务协调；代理数量和模型遵循当前授权及 `AGENTS.md`。换任务前留下一条可以直接执行的下一步。

## 验证与发布

在项目根目录执行 `pwsh -File scripts/verify.ps1`；只列出检查范围时加 `-List`。Windows 的现有本地工具通过包装脚本使用；普通 elan 环境和 Linux 使用 PATH 中的 Lake。单独定位问题仍可运行 `lake env lean 文件路径`。

CI 配置调用同一入口，新增检查文件不再需要手工把文件名写进工作流。mathlib 缓存列表仍是性能配置；新增领域时按实际导入更新，缓存未覆盖的模块由构建处理。

发布前检查要发布的文件集合、版本锁定和依赖使用示例。提交、推送、社区联系及新版本发布按当次授权执行；已发布标签保持不变。记录实际远端提交与 CI 结果，不能用旧绿色状态替新修改背书。

## 谁可以复用什么

Lean 用户通过 Lake 引用版本并导入定理，见[复用指南](REUSE.md)。研究者可复用任务模板与验证方法。Codex 用户可在这个仓库中调用 `$lean-research`，或复制完整 skill 文件夹到自己的仓库 `.agents/skills/`；其他代理也可直接阅读 `SKILL.md`，但应自行适配工具与目录。

项目内 skill 的结构校验不等于行为效果已得到独立实验证明。当前包含 F1 的验证经验、B686 多轮研究的纠偏，以及从研究组织报告中吸收的待实践规则；不声称新流程已被证明能提高解题率。通用分块 API、技能插件发布和学术收录均属于后续可选工作。
