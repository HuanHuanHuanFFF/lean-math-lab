# 仓库结构与并发研究

按数学问题归档，按独立研究批次分开记录。同一题的研究始终放在一个题目目录下；Git 分支、模型、会话和并发数量改变时，目录身份保持稳定。

## 从题目找到工作

| 位置 | 内容与职责 |
|---|---|
| `LEADER.md` | 控制中心职责、接管流程和当前整合入口；由 AGENTS 按职责触发，不复制数学前沿 |
| `research/README.md` | 题目索引，链接各题入口，不重复维护每批的详细进度 |
| `research/tasks/<题号>-<简称>/README.md` | 固定题面、结束条件、研究批次入口、正式模块与历史材料链接 |
| `research/tasks/<题号>-<简称>/runs/<批次名>/` | 一次独立推进的完整记录和工作文件 |
| `Math/`、`Math.lean` | 已接受的可复用 Lean 模块与稳定导入入口；从对应题目 README 链入 |
| `Tests/`、`Examples/` | 正式模块的题面对照、公理检查、边界检查与使用示例 |
| `research/shared/<事件名>/` | 确实跨题的环境、发布或维护证据；各题链接引用，数学结果留在各题内 |
| `research/external-results/<批次>/` | 外部报告、原始证据包、固定来源与接入对照；数学源码和新验收仍归对应题目批次 |
| `.tools/`、`.lake/` | 可重建工具、依赖和编译缓存，不作为研究交付提交 |

沿用已有题目 ID，如 `B686-Four`、`B677-Lcm`、`B699-Binomial`。同一问题不因换方法、换 Agent 或换分支而另建题目目录。正式库保留 `Math.B677` 等导入路径，题目入口负责让人从一个地方找到源码、实验和证明。

外部交付通过[外部成果索引](../research/external-results/README.md)按独立快照归档，保留原件、哈希、固定来源与署名。旧报告的接受状态另与本仓当前验收对照；采用的数学代码放入相应题目新批次并重新验证。外部原版验证、本仓移植验证、纸面论证与有限实验分别标记。

## 批次命名

新批次使用 `YYYYMMDD-topic-shortid`：

- 日期使用首次建立批次时的上海日期（Asia/Shanghai）。
- `topic` 是简短、可读的英文研究主题，使用小写字母、数字和连字符，例如 `lcm-distance`、`reflected-sum`。尚未选路线时可用 `exploration`，后续具体标题写在 README。
- `shortid` 是创建时生成一次的 6–8 位十六进制标识。检查已有本地及可见远端批次是否重名；重名且不是同一批次时重新生成。迁移已有记录可使用固定来源提交的短 SHA，注明它是来源标识。
- 名称创建后保持不变。模型、人员、当前分支和研究标题在 README 中更新，不编码进目录身份。多个批次不竞争 `round10`、`latest` 等共用名称。

例如，两份 B686 第九轮记录可分别命名为 `20260908-lcm-distance-7cab35e` 和 `20260908-reflected-sum-9bad0b9`，都放在 `research/tasks/B686-Four/runs/` 下，各自保留前沿、论证和验收。

Git 分支是承载工作和提交的工具，一个分支可包含多题或多个批次；它不决定文件归属。新分支的设备前缀、Leader 整合分支及 PR 发布规则见 [AGENTS.md 的 Contributions and Publication](../AGENTS.md#contributions-and-publication)，用户当次指定优先。合并到 main 后，批次目录不改名。Lean 导入含连字符的目录段时使用 `«…»`，按实际迁移后的完整路径编译检查。

## 批次内部文件

每批先创建 README；其余文件和目录按实际需要建立，不创建整套空目录。

| 批次内位置 | 内容 |
|---|---|
| `README.md` | 本批目标、状态、负责人及写入范围、预算、来源提交、接续批次、最后结果和下一步入口 |
| `frontier.md` | 本批对全题的判断：已采用的结果、准确假设、剩余无界参数、下一项检查 |
| `notes/` | 推导、文献适用性、路线比较、交流决策和失败原因，按主题命名 |
| `lean/` | 本批研究源码和消费者，接受状态由本批记录及验收证据说明 |
| `experiments/<实验主题>/` | 同一实验的脚本、输入、输出与解释放在一起，记录范围及运行命令 |
| `reviews/` | 独立审查、意见与处置，保留被修正的历史结论 |
| `verification/<UTC时间戳>/` | 一次验证的命令、依赖版本、源码哈希、日志、结论与未覆盖内容 |

并发子任务可在这些目录下按数学主题分配子目录，由 README 记录实际负责人。A/B、模型名和人物名可以作为交流来源，不作为长期唯一的文件导航方式。已有批次的内部布局可保持原样，由入口解释；迁移不要求同时整理全部内部文件。

题目 README 保持固定题面和导航。各批独立维护进度和 frontier，不拼接成共同报告。已有题目级 `frontier.md` 在有意迁移时保留来源快照，再作为导航；旧内容不能冒充其他批次的当前状态。索引暂未更新时，枚举 `runs/*/README.md` 仍应能找到已合入的批次。

沿用任务模板时，将目标、当前尝试、预算、前沿、证据和交接字段写入本批 README 或其链接文件；题目入口不承接这些高频变化字段。

## 开始、接续与切换并发

1. **确定题目和来源。** 读取题目入口及相关历史批次，核对同一结果是否已存在；写明本批实际采用的来源提交、路径与证据状态。刻意隔离的探索者仍遵循其输入包和首次交流边界。
2. **确定批次和写入归属。** 新的独立研究创建新批次；多个子 Agent 为同一批次协作时，使用本批内互不重叠的写入范围。共享 README、frontier 和公共模块各有一名协调者。
3. **按目标接续。** 新会话或新 Agent 接管同一目标，且已确认原负责人不再写入时，可以继续原批次并补记交接。独立并行探索或从多个旧批次组合新目标时，新建批次，逐项链接采用的结果，不复制整套旧目录。
4. **切换并发。** 单路拆成多路时，原批次可以继续，新增独立路线各建批次。多路回到单路时，暂停不再执行的批次并记录最后检查点；接续选定批次或建立新目标批次。并发数量变化本身不要求改名、搬文件或重写历史。

接续完成后，应能从本批 README 回答：谁在写哪里、基于哪个版本、采用了什么结果、还缺什么、下一步做什么。

## 随时合并研究分支

合并保存各批次已产生的文件与状态，可以在研究未完成时进行。Git 合并不提高数学结论的证据等级，也不表示仍在运行的批次已结束。

1. 按题目目录接入新批次，保留原提交来源、批次身份和独立报告。题目及总索引有冲突时逐项保留有效链接，不用一侧覆盖另一侧记录。
2. 同一批次的不同后继发生冲突时，确认是否共同推进同一目标。共同推进则逐文件核对差异和负责人；实际已成为独立探索则为分出的一支分配新批次名，记录分出基线。
3. 批次间复用优先链接或导入原模块，记录接受的来源版本及假设。需修改别人的冻结结果时，在本批建立有来源的修订，或由其负责人处理，并产生新验收证据。
4. 公共模块、依赖 pins、脚本和 CI 的重叠改动由整合者核查。先保存各批，再按实际需要提取公共模块；合并不要求把所有探索代码放入正式库。
5. 核验合并版本受影响的链接、导入、正式消费者及公理依赖，记录准确覆盖范围。仍在运行的批次由其负责人显式合入所需提交；协调工作目录，不能替其强制切换分支或覆盖文件。

## 移动文件与保存证据

迁移时，在题目内记录来源提交、旧路径、新路径、原因及必要的源码哈希映射。更新可执行源码的导入、脚本定位和当前版本链接，检查实际消费者；已发布的模块路径保留兼容入口。

原始日志、验收报告、输入输出与哈希清单按原字节保留。旧路径通过来源提交和迁移映射解释，不修改旧哈希来让新目录看似曾通过旧验证。历史相对链接若需旧目录语境才能解析，在入口提供固定提交链接。源码因导入或路径调整而变化时，新版本另做验收，旧成功记录仍属于旧源码。

验证输出使用新的时间戳目录，不能覆盖原记录。重跑旧脚本前检查写入位置：会覆盖原验收的脚本应在隔离副本执行，或以新入口另存结果。可重建缓存继续忽略；昂贵或不可忠实重建的实验结果、失败诊断与来源信息随批次保存。第三方原文按现有许可与仓库约定处理。

迁移清单记录的是迁移时的快照，不冻结批次后续推进。接续时可以更新本批前沿和源码，并产生新提交与新验收；不要为使旧哈希检查通过而改写迁移清单。重现迁移完整性检查应检出对应的迁移提交。

不要求为适配规则搬动所有历史轮次。优先处理同名冲突和正在接续的记录，其余历史路径保持可访问；新建独立研究使用新规则。当前三个分支的迁移与验收清单见[2026-09-08 布局迁移](RESEARCH_LAYOUT_20260908.md)。

## 验证与复用入口

在根目录执行 `pwsh -File scripts/verify.ps1`，加 `-List` 查看正式库、测试和示例范围。Windows 的现有工具通过包装脚本使用，普通 elan 环境和 Linux 使用 PATH 中的 Lake。单独检查使用 `lake env lean <文件>`。

正式 CI 不自动覆盖全部 `research/`。每批 README 链接专项验证入口并说明范围；未通过实验不因与已验证文件一起合入而变成已接受结果。源码 policy、编译、公理审计、AI 审查、人工同行评审、新颖性和公开状态分别记录。提交、推送及对外联系仍按当次授权执行。

Lean 库使用与稳定导入见[复用指南](REUSE.md)，数学研究决策见 [Lean 研究工作流](../.agents/skills/lean-research/SKILL.md)。本文负责目录、文件归属与接续，模型和并发上限由 [AGENTS.md](../AGENTS.md) 及用户当次要求决定。

## 已提取 ZIP 与重复材料

ZIP 接收、精确副本去重及历史路径恢复按[材料规则](ARTIFACTS.md)执行。全部成员有原字节保留路径后移除当前分支的原 ZIP，旧哈希与原 ZIP 的固定提交来源继续保留。需要读取、重跑或打包被去重的旧路径时，先使用恢复工具。完整批次导航见[生成目录](../research/CATALOG.md)。
