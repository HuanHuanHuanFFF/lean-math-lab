# REPLAY — 实际执行与回执层次

运行 `python replay.py`。

1. 核验SHA256SUMS.txt列出的包内文件。
2. evidence/verify.py 用二次环公式重算完整源周期，用原h/P/n方程接收FN31，用CRT小纤维核验同周期净差，核验10份新证书及来源字节。
3. evidence/generate.py 在临时目录重生成10份证书，与交付证书逐字节比较。
4. 检查证据目录的全部文件没有被重放修改。

首次打包使用PAYLOAD_SHA256SUMS.txt，只排除其自身、最终SHA清单及将由这次执行产生的回执/日志。该载荷ZIP在空目录解压并执行同样的数学接收；实际记录是CLEAN_REPLAY_RECEIPT.json及logs/clean_payload_replay.log。

随后把上述回执与日志加入最终ZIP，再对最终交付ZIP做第二次干净解压、CRC/SHA/数学接收/逐字节重生成/目录不变核验。最终ZIP的摘要和外附 `...evidence.validation.json` 绑定这个最终版本。最终ZIP摘要不写入自身，避免循环哈希；包内回执绑定已核验的数学载荷，而不是假称知道自身最终ZIP摘要。

两个实现均由本作者制作，不是外部独立审读。有限基值/周期核验不替代PROOFS.md中关于全部指数、整数恢复及覆盖范围的纸面论证。哈希完整性也不升级历史作者级前置。
