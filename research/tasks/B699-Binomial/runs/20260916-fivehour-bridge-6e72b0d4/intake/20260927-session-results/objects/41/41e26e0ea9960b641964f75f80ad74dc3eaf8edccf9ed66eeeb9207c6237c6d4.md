# Packaging and hash boundaries

为避免“压缩包包含自身 SHA-256”或“回执包含自身哈希”的循环，本轮分两层封装。

1. `PAYLOAD_SHA256SUMS.txt` 覆盖报告、证明、状态、脚本、证书、冻结来源及构建日志。它不包含自身、后生成的内部回执/干净日志和最终清单。
2. 对该 payload ZIP 真正执行新空目录解压、`verify.py`、前后字节树比较。回执保存为 `REPLAY_RECEIPT.json`，接收结果另存 `logs/clean_payload_verify.json`。
3. `SHA256SUMS.txt` 覆盖最终 ZIP 中除自身之外的所有文件，包括第一个清单和内部回执。
4. 生成最终 evidence ZIP。其 SHA-256 保存为外部同名 `.sha256`；随后再次新空目录解压并重放，外部 `*-final-replay.json` 记录最终 ZIP 自身哈希和实际结果。

因此内部回执是 **payload** 的回执，外部回执是 **最终 ZIP** 的回执，不能混称。两个层次都使用任意精度整数并校验解压树未被修改。临时解压目录在接收后移除，回执中的状态不表示后台仍在运行。

SHA-256、两次解压和同作者双算法验证是完整性/重算证据，不是 Lean 或外部独立审读。
