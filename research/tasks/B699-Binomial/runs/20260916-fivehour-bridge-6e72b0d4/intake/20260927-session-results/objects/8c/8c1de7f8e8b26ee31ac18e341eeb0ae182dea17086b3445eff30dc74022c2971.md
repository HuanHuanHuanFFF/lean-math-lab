# Packaging and replay

1. 冻结报告、证明、状态、来源、脚本、证书及构建日志，生成 PAYLOAD_SHA256SUMS.txt（不自哈希）。
2. 将该 payload 压缩，实际解压至新空临时目录并运行 verify.py。内部 REPLAY_RECEIPT.json 记录这次重放，logs/clean-payload-verification.json 保存完整接收输出。
3. 将内部回执与日志纳入最终 SHA256SUMS.txt（不自哈希），生成最终 evidence ZIP。
4. 对最终 ZIP 在另一个新空目录再运行重放。外部 `...-final-replay.json` 包含最终 ZIP 自身 SHA-256、文件数和接收输出；外部 `.zip.sha256` 给出简短校验行。

该顺序避免回执与归档哈希互相自引用。内部 receipt 的 payload archive hash 不等于最终 ZIP hash，二者范围在回执中显式区分。

所有数学及软件接收均为同作者验证，不是独立审读。verify.py 是只读检查；Python 缓存通过 -B/PYTHONDONTWRITEBYTECODE 禁止写入被验证目录。无仓库操作。
