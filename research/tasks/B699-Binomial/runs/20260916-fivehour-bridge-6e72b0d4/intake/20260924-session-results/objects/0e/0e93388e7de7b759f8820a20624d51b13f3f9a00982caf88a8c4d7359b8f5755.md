# Implementation correction: even-row source-count upper bound

An exploratory generic q4/q5 search used

```cpp
min(q, j/2+2)
```

as the maximum number of positive source multiplicities remaining in row index `j=0,...,5`.
This is too small by one on the even rows r=4,6,8. The correct number of available source values is

```cpp
(r/2)+1 = (j+3)/2+1,
```

so the safe bound is

```cpp
min(q,(j+3)/2+1).
```

The exploratory q4/q5 outputs were discarded and are not in this package. After correction and full rerun at both primes:

- q4 again left the same 17 residual configurations, all exactly reducible;
- q5 changed internal pruning counts slightly but still left zero residual configurations.

The q3 program already used the correct row-wise maximum and was unaffected.
