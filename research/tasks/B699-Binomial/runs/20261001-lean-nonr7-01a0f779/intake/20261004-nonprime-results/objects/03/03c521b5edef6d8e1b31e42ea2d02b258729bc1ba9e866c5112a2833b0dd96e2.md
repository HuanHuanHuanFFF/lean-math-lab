# 固定环境复验与完整性重放

以下 Lean 命令是**待原项目环境执行**的候选步骤，本轮没有成功执行它们。先在非仓库的隔离测试工作区准备与原环境相同的工具链和依赖，不要为此次检验运行会漂移版本的 `lake update`。

`input/original/environment/lean-toolchain` 与 `lake-manifest.json` 只是固定版本证据。把它们复制到空目录不等于得到完整 Lake 构建环境。

## A. 身份、核心探针与主模块（POSIX shell）

在已经配置好固定依赖的隔离工作区，放入主文件、探针、审计文件和可选对照文件。先记录实际版本、mathlib revision、缓存状态、源 SHA-256：

```sh
lake env lean --version
git -C .lake/packages/mathlib rev-parse HEAD
sha256sum NonprimeCertificates.lean CoreNumerals.lean AuditNonprimeCertificates.lean
lake env lean CoreNumerals.lean
lake env lean NonprimeCertificates.lean
```

版本应核对为 Lean v4.33.1 和 mathlib `0df444a360eaa60ab8c11dca51a86af692955474`。不要把本段写在文档里的值当作实际版本输出。

`CoreNumerals.lean` 不导入 mathlib；它先检查核心 successor 接口及全部数字，帮助区分核心名字/归约问题与 mathlib 导入问题。它的 print 指令也需要真实运行。

## B. 单独公理审计与 import 路径

直接 `lean NonprimeCertificates.lean` 不应被假定会生成可供另一个模块导入的 olean。显式写出输出，再把隔离目录加入已经由 Lake 建立的 LEAN_PATH：

```sh
lake env lean -o NonprimeCertificates.olean NonprimeCertificates.lean
lake env bash -c 'export LEAN_PATH="$PWD${LEAN_PATH:+:$LEAN_PATH}"; exec lean AuditNonprimeCertificates.lean'
```

第一条必须成功，第二条才能执行。审计文件包含五个乘积、十个非 1 条件、五个全限定名与短名、四个 successor 目标和 #print axioms。保留实际输出，不能只截取最后几行，不能将源码中的指令当成输出。检查 sorryAx 和其他非预期信任入口；库标准公理与新增公理区别处理，不预设必须是空列表。

## C. 方案对照及成本

```sh
lake env lean ImportOnly.lean
lake env lean CompareCertificates.lean
```

同名 mul_eq 替代文件须放到另一隔离工作区作为 `NonprimeCertificates.lean`，不要与主实现重复声明。可以重复相同编译/审计流程。记录启动/import成本、缓存状态、成功退出码、峰值内存和实际时间；一次 import-only 的相减不等于准确证明时间。旧 2.188 秒失败不构成成功方案对照。

记录器可捕获原始 stdout/stderr、命令、源码 SHA、退出码和总墙钟时间：

```sh
python3 repro/record_command.py --out /tmp/b699-new-compile-record --cwd "$PWD"   --source NonprimeCertificates.lean -- lake env lean NonprimeCertificates.lean
```

记录器不采集峰值内存，必须另加项目已采用的测量工具或诚实填写 null。它不负责安装/锁定工具链，不会自动把 requested_toolchain 当 actual_tool_versions。它的默认超时为 120 秒，可明确覆盖；超时会记录为 timeout，不是通过。

## D. 正常 checker 与消费者

精确项目 checker 命令 **未提供**，因此此处不写猜测命令。原执行者须使用项目正常入口，并另存命令、退出码、原始日志、版本、输入哈希及可得资源指标。没有运行这一项就不能写 checker 通过。

完成小文件检查后才考虑大型消费者回接。`integration/` 提供的是候选补丁，本轮没有套用到仓库。大消费者保留历史依赖缺失边界。

## E. 可在没有 Lean 时重放的检查

在交付目录中：

```sh
sha256sum -c SHA256SUMS.txt
python3 repro/static_check.py --root . --out /tmp/b699-new-static-record
```

使用新的空输出目录；脚本拒绝覆盖已有回执。static_check 只读取交付内容、在临时目录应用补丁、输出静态检查，不调用或模拟 Lean。

## F. ZIP 回执的范围与循环避免

`repro/package_evidence.py` 先把不含回执和最终清单的载荷制成临时 ZIP，实际解压并逐字节/SHA-256核对，随后把真实结果写入 `evidence/unpack-payload-receipt.json`。这份回执的对象是封装前载荷，不伪称是包含它自己的最终 ZIP。

接着生成只排除自己的 `SHA256SUMS.txt`，封装最终 ZIP，再在第二个临时目录真正解压。最终外置回执 `*.zip.UNPACK-RECEIPT.json` 记录最终 ZIP 哈希、每个成员哈希、manifest 核对、原交付目录比对和 CRC 结果；另有 `*.zip.sha256`。它们放在 ZIP 旁，不再回写入 ZIP。

要重建，请把源码/文档复制到新的非仓库目录并运行打包脚本。新运行的回执时间会不同，所以最终 ZIP 哈希也会不同；应该验证本次附件附带的实际哈希，而不是承诺重建包与旧包同一哈希。
