# 固定环境复现

## 前提

由原执行者在已经配置好指定依赖的项目或其隔离工作副本中执行。需要 Lean `leanprover/lean4:v4.33.1`、mathlib 提交 `0df444a360eaa60ab8c11dca51a86af692955474`，以及原项目确认的正常 kernel checker。原始锁定资料在 `input/environment/`。

本交付不是离线依赖安装包。根目录的 `lean-toolchain` 只声明目标版本；没有冒充完整项目的 lakefile 或依赖缓存。不要在交付目录直接运行 `lake update` 并误以为已复现原环境。

将 `NonprimeCertificates.lean`、`AuditNonprimeCertificates.lean`、`ImportOnly.lean` 放到该固定项目的可编译位置；以下命令假定它们在当前项目根目录。审计文件自包含主源码，不需要先配置新模块的 import，也不依赖原 129 个大型消费者依赖。

## 版本核对与最小检查

```bash
cat lean-toolchain
lake env lean --version
git -C .lake/packages/mathlib rev-parse HEAD
sha256sum NonprimeCertificates.lean

lake env lean NonprimeCertificates.lean
lake env lean AuditNonprimeCertificates.lean
```

必须核实有效 Lean 版本和 mathlib HEAD 确实匹配；不能只看 `lean-toolchain` 文件或原 manifest 就认定当前二进制、源码和缓存都匹配。实际依赖不在默认目录时，按原项目解析出的路径核对。

`AuditNonprimeCertificates.lean` 检查两个采用的库接口，打印两个基础库引理与五个具名证书的公理依赖，并检查四个后继参数类型。它由 `NonprimeCertificates.lean` 原字节和 `audit/AuditCommands.lean.inc` 拼接而成；生产主文件改动后应重新拼接，不要让二者漂移。该文件是审计目标，不要 import 到生产消费者。

记录完整输出，确认五个声明各有实际审计结果，并确认整个编译进程退出 0；出现声明输出但随后编译失败不构成成功。

## 编译对象与记录

项目 checker 若需要 `.olean`，可显式输出独立对象：

```bash
lake env lean -o NonprimeCertificates.olean NonprimeCertificates.lean
```

成功后绑定 `.olean` SHA、主源码 SHA、真实编译命令、有效 Lean 版本、mathlib 提交和缓存状态。不要把上一次失败遗留的 `.olean` 当成本次输出。

包内通用记录器的示例（运行于固定项目；`PACKET` 应设置为本交付的绝对路径，`OUT` 为一个新的记录目录）：

```bash
python3 "$PACKET/scripts/capture_command.py"   --cwd "$PWD" --out "$OUT" --label compile   --source "$PWD/NonprimeCertificates.lean"   -- lake env lean -o NonprimeCertificates.olean NonprimeCertificates.lean

python3 "$PACKET/scripts/capture_command.py"   --cwd "$PWD" --out "$OUT" --label audit   --source "$PWD/AuditNonprimeCertificates.lean"   -- lake env lean AuditNonprimeCertificates.lean
```

记录器默认超时为 120 秒，可通过其 `--timeout` 参数显式调整；超时将杀死该命令的独立进程组并记录为超时，不报告通过。它会拒绝覆盖同名记录。其 `proof_acceptance` 故意保持 `null`，命令成功与证明接受应由原执行者按完整日志、实际公理输出和 checker 结果分别判断。

## 独立 kernel checker

**本包没有准确 checker 入口，因此不提供猜测命令。**

原执行者应运行其已经确认的正常 kernel checker，对本次生成且 SHA 绑定的对象执行检查，独立保存准确 argv、二进制版本／SHA、退出码、完整 stdout/stderr、耗时和可得峰值内存。可用同一命令记录器包装真实 argv；不要将一个猜测的 `leanchecker` 命令当作原项目入口。

`lake env lean` 和 `#print axioms` 都不能替代任务要求的这一步。

## 公理与性能口径

检查无 `sorryAx`、无未经许可新增公理或新的反射信任入口。对 `propext`、`Classical.choice`、`Quot.sound` 等既有标准公理与新增公理分类，而不是把所有标准公理都误报为新增；不要事先硬编码本候选一定依赖哪几个。

编译与 checker 分别计时，说明是否包含 shell、Lake、进程启动、import 与输出对象写入。记录 mathlib `.olean` 缓存与操作系统页缓存状态；不得用单次 `ImportOnly.lean` 的时间差宣称精确的“纯定理耗时”。同环境成功方案方可作性能比较；原 2.188 秒失败记录不合格。
