# 仅使用已有环境的最小验收

**本文件中的成功路径均未在本轮运行。** 不安装 Lean，不运行 elan/lake 的安装或依赖获取动作，不构建依赖，不修改项目仓库，不猜测 checker 命令。

## 入口 A：已有环境的只读预检与记录器

```bash
python repro/replay_existing.py   --lean /absolute/existing/lean-v4.33.1/bin/lean   --project /absolute/existing/pinned-project   --out /absolute/new/directory-outside-project-and-delivery
```

三个路径是需要替换的真实路径，不是本环境存在的路径。`--lean` 必须是已安装工具链的 native 二进制，不得为 elan shim。输出目录必须不存在，并位于项目和交付目录之外。

脚本核对 --version 的 4.33.1 与锁定 commit 前缀、project toolchain/manifest、各依赖现有 git HEAD、四份完整 mathlib 源文本的规范化 SHA-256；依赖构建缓存必须已存在。不调用 lake、elan、git checkout、git fetch、lake build 或 cache get。所有新源码、olean 与日志只写入新输出目录。它的实际 Lean 分支未测；预检阻断不是证书不成立。

运行顺序为 CoreNumerals、ImportOnly、SignatureAudit、NonprimeDefsOnly、TypeAudit、AxiomAudit。关闭自动隐参数与异步 elaboration，所有阶段顺序成功才继续；新输出目录位于 LEAN_PATH 最前端，不使用旧项目的同名主模块对象。

## 入口 B：对应的精确最小编译形式

在仓库外新目录，复制本包根目录的六个待验收 .lean 文件；设置 LEAN 为同一个已有 native 二进制，PINNED_PACKAGE_LEAN_PATH 为所有预建固定依赖的 lib/lean 目录，以平台路径分隔符连接。POSIX shell 形式：

```bash
set -eu
export LEAN_PATH="$PWD:$PINNED_PACKAGE_LEAN_PATH"
"$LEAN" --version
"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$PWD" SignatureAudit.lean
"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$PWD" -o NonprimeDefsOnly.olean NonprimeDefsOnly.lean
"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$PWD" TypeAudit.lean
"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$PWD" AxiomAudit.lean
```

所有命令只处理新目录。手动入口仍须先核对上文版本、源与对象来源。不要在主编译非零后继续用缓存中的旧 olean 审计。`CoreNumerals.lean` / `ImportOnly.lean` 可独立运行作故障定位与启动/导入口径对照；二者不等于主目标验收。

## 必须保留的公理输出

AxiomAudit 打印 Nat.Prime、Irreducible.isUnit_or_isUnit、Nat.isUnit_iff、Nat.succ_succ_ne_one 与五个新定理的公理依赖。要求记录未经改写的原始 stdout/stderr。若出现 sorryAx、Lean.ofReduceBool / Lean.ofReduceNat 等非预期信任入口必须拒绝并查明；即使这些词未出现，也要人工审阅完整公理列表，不能自动称为“零公理”。

normal checker 由原项目提供已确认的准确入口并记录；本包没有伪造或猜测该命令。最小文件编译并不表示已有依赖对象被独立重检，更不表示完整消费者通过。

## 可证伪对照

`negative-tests/ReversedGenericEquality.lean` 应因把 a*b=n 直接给需要 n=a*b 的字段而拒绝；`WrongSuccessorOffset.lean` 应因 2444≠1 无法当作 2442≠1 而拒绝。两者均未运行，所谓“应拒绝”是测试预期，不是记录。

## 性能比较要求

旧 Basic 源码保留在 reference/ 中。比较时以两个分离新目录、相同 Lean/依赖版本、相同资源和缓存状态运行，分别记录 import-only、五条主声明、公理打印和 normal checker。原大型消费者若已导入 Basic，则另行记录其真正端到端收益，不从独立模块的 header 变化外推。
