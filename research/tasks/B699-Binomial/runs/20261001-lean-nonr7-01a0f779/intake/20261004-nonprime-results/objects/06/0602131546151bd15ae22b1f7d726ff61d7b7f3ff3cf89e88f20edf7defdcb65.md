# 固定环境补验步骤

**以下是供原项目执行者使用的复现说明；本轮没有运行成功。** 原源码的数学接口来自所附快照；此包不是完整离线 Lake 项目，不包含可用的完整依赖缓存。

## 1. 准备与版本核对

在已经配置指定依赖的项目工作副本中，将 `NonprimeCertificates.lean`、`AuditNonprimeCertificates.lean` 和可选的 `repro/ImportOnly.lean` 放到该工作副本根目录，保持文件名。此操作由原执行者完成；本轮没有把这些文件放入或修改原仓库。

以下 shell 片段按 Bash 编写。`CERT` 指向本交付包的解压目录；`OUT` 选择一个新的证据输出目录，不覆盖本包已有 `evidence/`。先 `cd` 到上述已配置项目根目录。

```bash
set -euo pipefail
CERT=/absolute/path/to/B699-nonprime-certificates-20261003
OUT=/absolute/path/to/new-validation-evidence

python3 "$CERT/repro/record_command.py" \
  --kind fixed_environment_preflight --out "$OUT/preflight" \
  --source lean-toolchain --source lake-manifest.json \
  --source NonprimeCertificates.lean \
  -- bash -c '
    set -euo pipefail
    test "$(cat lean-toolchain)" = "leanprover/lean4:v4.33.1"
    revision="$(git -C .lake/packages/mathlib rev-parse HEAD)"
    printf "mathlib HEAD: %s\n" "$revision"
    test "$revision" = "0df444a360eaa60ab8c11dca51a86af692955474"
    version="$(lake env lean --version)"
    printf "%s\n" "$version"
    printf "%s\n" "$version" | grep -E "version 4\.33\.1([, )]|$)"
    sha256sum .lake/packages/mathlib/Mathlib/Data/Nat/Prime/Basic.lean
  '
```

还应检查依赖工作树没有未记录修改；仅匹配 `git rev-parse HEAD` 并不能证明工作树干净。输入中的 `Prime-Basic.lean` SHA-256 为：

```text
6d3fbe9eafe2c8bef5f390528ba3bb7e7503be47607154d64f1add45cda17349
```

包中 `input/` 保存原始 toolchain、manifest 和 reference 快照，方便进一步逐字节核对。若版本或源码不符，应停止并报告，不静默改用其他 Lean/mathlib 版本。

## 2. 最小编译

题目给定的最小形式保持不变：

```bash
lake env lean NonprimeCertificates.lean
```

带真实记录的等价执行如下，不改变递归深度、内存上限或证明信任设置：

```bash
python3 "$CERT/repro/record_command.py" \
  --kind lean_source_check --out "$OUT/source-check" --gnu-time \
  --source NonprimeCertificates.lean \
  -- lake env lean NonprimeCertificates.lean
```

`--gnu-time` 只是记录器选项。系统有 `/usr/bin/time` 时记录其 RSS 与时间；没有则只记录可得的墙钟信息。必须查看真正的 `command_exit_code`、原始 stdout/stderr 和未解决目标，不只看辅助脚本是否产出了 JSON。

可选 import-only 对照：

```bash
python3 "$CERT/repro/record_command.py" \
  --kind import_only --out "$OUT/import-only" --gnu-time \
  --source ImportOnly.lean \
  -- lake env lean ImportOnly.lean
```

记录执行顺序、现有依赖 `.olean` 缓存及 OS 页缓存状态。首次调用不自动意味着冷缓存；总墙钟差不是严格的纯证明成本。

## 3. 生成对象、取得真正类型和公理输出

审计文件要导入新模块，先在当前根目录生成对应对象：

```bash
python3 "$CERT/repro/record_command.py" \
  --kind lean_object_build --out "$OUT/object-build" --gnu-time \
  --source NonprimeCertificates.lean \
  -- lake env lean -o NonprimeCertificates.olean NonprimeCertificates.lean

LEAN_PATH="$PWD${LEAN_PATH:+:$LEAN_PATH}" \
python3 "$CERT/repro/record_command.py" \
  --kind type_and_axiom_audit --out "$OUT/axioms" --gnu-time \
  --source NonprimeCertificates.lean --source NonprimeCertificates.olean \
  --source AuditNonprimeCertificates.lean \
  -- lake env lean AuditNonprimeCertificates.lean
```

根目录被显式加到 `LEAN_PATH`，以便审计文件找到刚生成的 `NonprimeCertificates.olean`。若将模块放在更深项目路径，应改成相应的正常模块名与构建输出路径。上述两个 `.lean` 文件及所有输出对象必须来自本次已绑定源码，不使用来源不明的同名旧对象。

必须保留审计 stdout 原件。它应包含五个明确目标类型、四个 successor 类型检查，以及所选库引理和五个具名结论的实际公理输出。本说明不预填输出内容。

接受时区分库标准公理 `propext`、`Classical.choice`、`Quot.sound` 与 `sorryAx`、新增公理或额外 native 信任入口，逐一审阅实际完整依赖集合。单纯源码 grep 不能替代这一步。
