## 推荐入口：直接调用已经安装的原生 Lean

使用 Python 3.10+。准备一个已存在且依赖预构建完成的原项目或隔离副本：toolchain 必须为 `leanprover/lean4:v4.33.1`；manifest 的包名／revision 集合应与附件一致；mathlib HEAD 必须为 `0df444a360eaa60ab8c11dca51a86af692955474`。

脚本不会安装 Lean，不会调用 elan/Lake，不会构建或拉取依赖。它拒绝缺失工具、工具链 shim、不同 pin 和缺失预构建缓存。只读项目源码／锁文件／依赖，全部新对象与日志写入项目和本包之外的新目录。

```bash
PACKET='/绝对路径/B699-Nonprime-StructureReview-20261003'
PROJECT='/绝对路径/已准备好的固定项目'
LEAN_BIN="$HOME/.elan/toolchains/leanprover--lean4---v4.33.1/bin/lean"
OUT='/绝对路径/尚不存在的独立审计输出目录'

PYTHONDONTWRITEBYTECODE=1 python3 "$PACKET/scripts/replay_no_install.py"   --project "$PROJECT"   --lean-bin "$LEAN_BIN"   --out "$OUT"
```

只替换以上四个位置参数；`LEAN_BIN` 必须是已经安装的真实发行版 `bin/lean`，不是可能自动安装的 `$HOME/.elan/bin/lean`。若真实发行版在其他目录，直接填入其绝对路径。`OUT` 必须不存在且在项目和本包目录之外，防止旧对象与记录混入本次结果。

脚本先静态检查锁、依赖对象目录及附件中的两份 mathlib 源码，再记录实际 `lean --version`、mathlib `git rev-parse HEAD`。仅这些条件均符合时，设置显式绝对依赖对象目录的 `LEAN_PATH`，依次执行：

```bash
# LEAN_PATH 由上面的脚本按锁文件中已存在的依赖对象目录设置。
"$LEAN_BIN" -j1 -DElab.async=false -R "$PACKET" "$PACKET/ImportOnly.lean"
"$LEAN_BIN" -j1 -DElab.async=false -R "$PACKET"   -o "$OUT/NonprimeCertificates.olean" "$PACKET/NonprimeCertificates.lean"
"$LEAN_BIN" -j1 -DElab.async=false -R "$PACKET" "$PACKET/AuditNonprimeCertificates.lean"
"$LEAN_BIN" -j1 -DElab.async=false -R "$PACKET"   -o "$OUT/DivisorCertificates.olean" "$PACKET/comparison/DivisorCertificates.lean"
"$LEAN_BIN" -j1 -DElab.async=false -R "$PACKET" "$PACKET/AuditComparison.lean"
```

每个命令有独立 argv、源哈希、退出码、完整 stdout/stderr、命令总墙钟时间记录。源码不同、超时、编译非零退出或缺少请求对象，都不报告完成。对象新生成后另绑定 SHA-256。首次命令失败就停止后续步骤，保留失败证据。

仅检查 `.olean` 存在不能证明其构建来源；操作者仍需保证缓存与固定源码一致。脚本不伪造缓存 provenance，也不控制系统页缓存。Python 脚本的解析与 `--help` 本轮已检查，执行到 Lean 的路径仍未实测。

## 公理与类型审计

`AuditNonprimeCertificates.lean` 以推荐源文件原字节为前缀，检查推荐接口、五个精确结论、公理输出与四个后继接缝。`AuditComparison.lean` 同时包含两套原始声明、准确接口检查、15 个具体整除义务、十条公理输出和 `pp.all` 声明打印。两个文件各自只需 mathlib import，无新本地 `.olean` 导入前提。

整个进程退出 0 后，再逐项检查每个具名定理真实公理列表：不能有 `sorryAx` 或未经批准的新信任入口。应区分库标准公理与新增公理，不能将空 stdout 当作无公理，也不能把已打印若干结果但最终报错的审计视为成功。未预填任何预期列表。

## 原项目正常 kernel checker

附件没有给出可执行的正常 checker 准确入口，本轮也没有 checker 环境，因此不能给出凭空猜测的 checker 命令。上面的 Lean 和公理打印不替代这一项。

## 性能口径

脚本记录的是整个独立命令耗时，包括启动、导入与对象写入；没有采集峰值内存，字段为 null。`ImportOnly.lean` 是参考基线，不可用单次时间差宣称精确的纯证明成本。两份 audit 打印数量不同，更不能拿两份 audit 总耗时直接作证明优劣比较。

要比较实际性能，只比较同环境、同 flags、同缓存口径且成功的生产与整除文件编译／checker，必要时重复并交换次序。当前脚本是重放记录器，不是设计好的微基准。历史 2.188 秒失败记录不作为成功对照。
