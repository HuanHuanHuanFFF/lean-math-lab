## 编译尝试的准确口径

实际尝试的参数数组：

```text
["lake", "env", "lean", "NonprimeCertificates.lean"]
```

记录中的时间戳为 `2026-10-03T14:44:18.172214+00:00`（UTC；以容器时钟记录）。系统在启动阶段返回：

```text
FileNotFoundError: [Errno 2] No such file or directory: 'lake'
```

因此 Lean/Lake 进程没有启动，**不存在 Lean 退出码**。`command_exit_code = null`；辅助记录器自身以 127 退出。`attempt_wall_seconds` 仅表示 Python 尝试启动失败的时间，绝不是编译耗时。编译耗时、编译峰值内存、checker 耗时和 checker 峰值内存均记为 `null`，不能填 0，也不能用探测进程的耗时替代。

`stdout.log` 与 `stderr.log` 为空，因为目标进程没有启动；系统启动错误单独保存在 `launch-error.log`。这些不是成功编译的空日志。

当前交付目录也不是已经安装好依赖的 Lake 项目；ZIP 中只有指定版本信息和两份 mathlib 源码快照。本轮没有重建完整依赖环境，不能在仅安装一个 Lean 可执行文件后就把此目录当作已配置项目。
