# 固定源码对抗审查报告

## 0. 证据等级与结论

对象是用户当前消息给出的 Defs-only 4884 例子，而不是默认接受另一会话的结论。固定 Lean `leanprover/lean4:v4.33.1`，标签本轮只读解析到 `819816b2e0a3bf405af45ae5c7af2491d8f5bee6`；固定 mathlib `0df444a360eaa60ab8c11dca51a86af692955474`。

**没有发现这份候选在读取到的冻结源码中存在类型方向或参数错误。可保留为候选；没有实测编译。** 四份完整 mathlib 源码经过本轮 Git blob 校验；Lean 核心只保留精确摘录，摘录哈希不是整文件哈希。

## 1. 原始目标并未被替换

`Mathlib/Data/Nat/Prime/Defs.lean:34,41–46` 在 `namespace Nat` 定义 `def Prime (p : ℕ) := Irreducible p`，其 `irreducible_iff_nat_prime` 用 `Iff.rfl`。

因此本版本中 `h : Nat.Prime n` 可在定义相等意义上作为 `h : Irreducible n` 使用，不需要把一般的 `_root_.Prime` 与 Nat.Prime 通过 `Nat.prime_iff` 连接。本候选不使用 `_root_.Prime`；更不定义或偷换为名叫 CorePrime 的新谓词。`fun h => ...` 的 h 是否定目标自身展开为 `Nat.Prime n → False` 后引入的局部变量，不是新加在定理外层的假设。

`CoreNumerals.lean` 只证明算术探针，没有任何 Nat.Prime 证明，不能拿它冒充原目标的 core-only 证书。

## 2. 投影的精确来源与方向

`Mathlib/Algebra/Group/Irreducible/Defs.lean:36–48` 在 `[Monoid M]` 的 section 中定义结构：

```lean
structure Irreducible (p : M) : Prop where
  not_isUnit : ¬IsUnit p
  isUnit_or_isUnit ⦃a b : M⦄ : p = a * b → IsUnit a ∨ IsUnit b
```

字段实际全名为 `Irreducible.isUnit_or_isUnit`，不是要求存在一个叫 `Nat.Prime.isUnit_or_isUnit` 的独立定理。`a`、`b` 是可按名实例化的严格隐式参数，接收的等式方向是 **p = a*b**，并不是 a*b=p。

`Nat.Prime` 定义展开后暴露 Irreducible 接收者；`Prime.Defs:88–95` 自身已有 `pp.isUnit_or_isUnit hn` 的用法，支持原 dot 写法的来源审查。仍未在此容器实际运行 dot elaboration。

`SignatureAudit.lean` 同时准备了以下泛型测试：

```lean
example {n a b : Nat} (h : Nat.Prime n) (e : n = a * b) :
    IsUnit a ∨ IsUnit b :=
  h.isUnit_or_isUnit (a := a) (b := b) e

example {n a b : Nat} (h : Nat.Prime n) (e : n = a * b) :
    IsUnit a ∨ IsUnit b :=
  Irreducible.isUnit_or_isUnit h (a := a) (b := b) e
```

反向假设 `e : a*b=n` 必须传 `Eq.symm e`。数值闭合实例的 rfl 不能单独暴露方向误读，因为两边本来就会归约成同一数值。故专门准备泛型正例及 `negative-tests/ReversedGenericEquality.lean`，后者期待失败但没有运行。

## 3. 单位到 1 的方向与真正依赖

`Mathlib/Algebra/Group/Nat/Units.lean:38`：

```lean
protected lemma isUnit_iff {n : ℕ} : IsUnit n ↔ n = 1 := isUnit_iff_eq_one
```

它是 protected，但调用使用了准确限定名 `Nat.isUnit_iff`，没有依赖 `open Nat` 将短名开放。因此 `u : IsUnit a` 给出 `Nat.isUnit_iff.mp u : a = 1`，不是 `1 = a`，也不是需要 `.mpr` 的方向。

`IsUnit` 是 mathlib 的单位谓词：在 `Mathlib/Algebra/Group/Units/Defs.lean` 中定义为存在单位 u，其值等于给定元素。`isUnit_iff_eq_one` 在 `[Monoid M] [Subsingleton Mˣ]` 下建立；Nat 专用 lemma 的这些类型类依赖已在库声明中实例化。Nat 单位文件自身提供 `unique_units`，由 `Nat.units_eq_one` 支持。该库依赖不能被描述成“全部是 Lean core”；也不能据其源码样式就断言公理输出为空。

Lean 固定核心 `src/Init/Data/Nat/Basic.lean:653`：

```lean
theorem succ_succ_ne_one (a : Nat) : succ (succ a) ≠ 1 := nofun
```

`Nat.succ_succ_ne_one k` 是 `succ (succ k) = 1 → False`。例如 k=2440 时，其参数类型定义归约为 `2442 = 1`，与第二分支的 `Nat.isUnit_iff.mp u` 完全对应。这里不需要 `.symm`。

五个乘积和十个加 2 对应关系已经用 Python 整数运算检查，并从实际交付源码匹配。Lean 定义相等的判断只是源码审查，没有执行验证。

以 4884 为例，h 的目标始终是原始 `Nat.Prime 4884`。字段产生 `IsUnit 2 ∨ IsUnit 2442`；左、右分支分别得到 `2=1`、`2442=1`，再由对应非 1 证书推出 False。Or.elim 的两个分支目标均为 False。本方案没有使用完整分解，也没有假设余因子素性。

## 5. import 与命名空间

Defs 顶层 public imports 为 Nat.Units、GroupWithZero.Nat、Algebra.Prime.Defs、Nat.Sqrt、Order.Basic。Algebra.Prime.Defs public import Irreducible.Defs，后者 public import Group.Units.Defs。需要的库声明已位于这些公开导入路径中；无须再导入 Prime.Basic。

主文件保留 `B699CompositeTransfer20261003`，五个全限定名与前轮一致。TypeAudit 测试 `_root_.Nat.Prime`、命名空间内部短名及四个 `(i + 1)` 目标。旧 Basic 主文件与新 Defs-only 文件互为替代，不得同时导入产生同名声明冲突。

`Prime.Defs` 不仅有“定义”：它还带入相关算术、平方根、最小素因子和可判定实例等库内容。Defs-only 不意味着一个独立 core-only 环境，也没有原依赖缓存时的离线可构建保证。

## 6. 递归与 elaboration 风险

本源码没有调用整个 Nat.Prime 的 Decidable 实例。字段投影从假设 h 获得析取，不是在算出 n 是否素数。rfl 仍要求闭合自然数乘法的定义归约，两个非 1 项仍要求 successor 与字面量的定义归约。

固定 Lean `Lean.Meta.WHNF` 的 reduceNat? 和固定内核 type_checker 的 reduce_nat 都有 Nat.mul / Nat.succ 的数值路径。这里 a、b 显式给定，没有让 elaborator 从未知因子的乘积反推分解。因此没有发现重新引入原素性决策递归的源码路径。

不能由此声称没有任何递归、资源限制一定不触发或有某个具体时间上界。相对于单次 not_prime_mul 应用，新项多了局部 lambda、结构字段访问、Or.elim、rfl、Iff.mp 等 elaboration 工作；自动隐参数、异步 elaboration、导入路径、旧对象污染等仍要实际测试。交付不改变 maxRecDepth 或 heartbeats。

## 7. 与已有 not_prime_mul 主版本的实质比较

### 导入图

旧文件直接导入 Prime.Basic；Basic 自身 public import Prime.Defs，并另外直入 GroupWithZero.Associated 和 Ring.Parity。新文件只直接导入 Prime.Defs。因而新路线没有新增外部模块需求，它缩小的是被请求的导入层次。不能把两条额外 header import 简单当成“恰好少两个传递模块”，本轮没有枚举完整导入图。

### 新证明的直接引用

旧文件直接应用 `Nat.not_prime_mul` 与两个 `Nat.succ_succ_ne_one`。新文件不再引用 not_prime_mul，而显式使用 Irreducible 字段、Or.elim、Eq.refl、Nat.isUnit_iff / Iff.mp，以及两个非 1 证书。这些“新增显式引用”原本已经在 Basic 可用的库环境内，并非新增公理或新增模块的证据。

旧 not_prime_mul 的源码经 prime_mul_iff 使用一般不可约乘积等价式。新证书绕过这层高阶定理接口，直接取出不可约元的一个字段。但 Nat.isUnit_iff 的底层单位理论仍在，且结构投影依赖固定版本 Nat.Prime 的具体定义。not_prime_mul 的接口更封装，面对未来定义重构更少暴露实现细节；本任务固定版本下这只是维护权衡。

### 能报告和不能报告的收益

能报告：主模块不再导入 Basic，不再引用 not_prime_mul，直接证明原始目标，字段的合同和分支都可逐步检查。
不能报告：导入秒数、内存、完整表达式节点数、checker 时间、精确传递模块数量或公理集合改善。单个已导入定理的应用本来就不重新执行其源码里的 simp；不能把“避免重新跑 simp”当成新方案的收益。如果大型消费者本来已传递导入 Basic，改这一个小模块未必降低其总导入成本。

**本轮不凭静态数据撤换上一轮选定的 not_prime_mul 集成主版本。Defs-only 是有来源支持的轻导入候选，实际选择仍需同环境测量；不是新增数学闭合或 Lean 验收。**
