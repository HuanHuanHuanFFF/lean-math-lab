## 1. 固定附件中的准确接口

先阅读原包 `START-HERE.md`，再阅读 `source/CompositeTransferLegacy.lean`、`evidence/stdout.log` 和 `receipt.json`，最后核对 `reference/Prime-Basic.lean`。当前独立包将这些原件保存到 `input/original/`。

`input/original/reference/Prime-Basic.lean` 第 31–32 行：

```lean
theorem not_prime_of_mul_eq {a b n : ℕ} (h : a * b = n)
    (h₁ : a ≠ 1) (h₂ : b ≠ 1) : ¬Prime n :=
  h ▸ not_prime_mul h₁ h₂
```

第 73–77 行（以下保留原接口与实现）：

```lean
theorem not_prime_of_dvd_of_ne {m n : ℕ}
    (h1 : m ∣ n) (h2 : m ≠ 1) (h3 : m ≠ n) : ¬Prime n :=
  fun h => Or.elim (h.eq_one_or_self_of_dvd m h1) h2 h3

theorem not_prime_of_dvd_of_lt {m n : ℕ}
    (h1 : m ∣ n) (h2 : 2 ≤ m) (h3 : m < n) : ¬Prime n :=
  not_prime_of_dvd_of_ne h1 (ne_of_gt h2) (ne_of_lt h3)
```

以上处于 `Nat` 命名空间。特别是 `not_prime_of_dvd_of_lt` 的第二个参数准确为 `2 ≤ m`，不是仅有 `m ≠ 1`；第三个参数为严格上界 `m < n`。两个根引理均不要求因子为素数，不需要完整分解余因子。

这里的固定版本绑定是附件 toolchain、manifest、PROVENANCE 及对应成员 SHA；并未运行固定库，也没有重新取得公开固定提交的原始字节。公开固定 URL 本轮抓取失败，不能把上一轮网页可读的叙述当成本轮新验证。详见 `sources/WEB_LOOKUP.json`。

## 2. 五个完全不含 decide 的整除候选

`comparison/DivisorCertificates.lean` 只导入与推荐方案相同的 `Mathlib.Data.Nat.Prime.Basic`，没有引入算术 tactic。以第一个数为例：

```lean
theorem not_prime_4884 : ¬ Nat.Prime 4884 :=
  Nat.not_prime_of_dvd_of_lt (m := 2) ⟨2442, rfl⟩
    (Nat.le_refl 2) (Nat.le_add_right 3 4881)
```

`⟨2442, rfl⟩` 把给定余因子装入整除的存在见证，`rfl` 核验闭合乘法等式。`Nat.le_refl 2` 给出 `2 ≤ 2`；`Nat.le_add_right 3 4881` 的声明结果为 `3 ≤ 3 + 4881`，对闭合数值通过定义相等拟用作 `2 < 4884`。

`Nat.le_add_right (n k : Nat) : n ≤ n + k` 的接口可见于 Lean 官方现行 API 文档，但该文档不是 v4.33.1 固定快照，附件也未包含对应完整核心源。因此新辅助接口的固定版本可用性和上述定义相等接缝仍须运行审计，不能声称已通过。`AuditComparison.lean` 包含辅助引理的精确类型 ascription 与每条具体义务的独立 `#check`。

所有乘积、上下界算术和偏移量已由 Python 精确整数运算重核；Python 结果不代替 Lean。五个最终定理都没有额外对调用者暴露的假设。

两个通用引理的适用域不能不加条件称为完全相同：乘积版允许零因子的情形，而 `2 ≤ m < n` 排除了 `n=0`。本次五组因子和余因子都至少为 2，所以它们在本次具体证书上都足够。

## 3. 证明项结构，而不只是字数

乘积版每条直接应用 `Nat.not_prime_of_mul_eq`，提供一个 `rfl` 和两个 `Nat.succ_succ_ne_one` 实例。整除版每条直接应用 `Nat.not_prime_of_dvd_of_lt`，提供一个包含 `rfl` 的存在见证，以及两个序证明项。两者根引理都有三个命题证明参数。

整除版没有省去给定乘积的核验，而是在其外增加存在见证构造；它还需要匹配严格序与非严格序、后继及闭合加法的类型。乘积版需要匹配两个因子的后继表示以及闭合乘法等式。这个描述是源码可见的构造骨架，不是实际打印的 Expr，也不是完整 AST 节点计数。

另一方面，不能夸大整除版的成本：`Nat.le_add_right 3 4881` 是对已有库定理的实例化，不是在这个证书里手写 4881 个 `Nat.le.step`。也不应将两个根引理的库证明体全部展开后计字数，冒充每个下游调用必须重复归约的成本。现有定理常量、隐式参数、存在谓词、共享和 elaboration 会影响实际项结构；必须以固定环境的实际声明与检查记录判断。

本轮没有证明哪一版的 Expr 更小，也没有证明哪一版的内核时间更短。`AuditComparison.lean` 的 `set_option pp.all true in #print ...` 用于以后读取实际声明，不预填输出。

## 5. 调用复杂度与保留理由

两版都能保持相同的公开定理类型：`¬ Nat.Prime 4884` 至 `¬ Nat.Prime 4888`。下游四个调用各引用两个定理常量；五个定理复用八次。更换证明正文不减少八个参数位置，也不缩短后继索引的逻辑接口。通用 `common_succ_of_nonprime` 无需改动。

整除方案唯一已量化的改善是少 25 个归一化 UTF-8 源字节。这不是实际证明成本优势，同时引入了本轮未在固定核心环境验证的序接口。保留已经交付的、直接表达给定因子的乘积方案更符合本次目标。这个决定并非断言整除版一定更慢，更不是已经证明乘积版全局最优。

最终推荐文件、定理命名空间和调用补丁全部沿用前轮原字节；本轮增量补丁为零。对仍使用最初 `by decide` 源码的环境，包中继续附原有迁移补丁；没有在仓库应用。临时副本上的补丁核对通过只说明文本变换精确。
