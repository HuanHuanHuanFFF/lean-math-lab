## 2. 因子及 successor 实参逐项核对

`Nat.succ_succ_ne_one k` 的公开 API 类型为 `Nat.succ (Nat.succ k) ≠ 1`。随包固定 mathlib 源码在 `Prime-Basic.lean:239–241` 已直接把 `Nat.succ_succ_ne_one n` 用于 `n + 2 ≠ 1`。本轮根据这一接口实例化，未用 `_` 猜测因子。

|结论 n|乘积等式|第一个实参 k|k+2|第二个实参 l|l+2|
|---:|---|---:|---:|---:|---:|
|4884|2 × 2442 = 4884|0|2|2440|2442|
|4885|5 × 977 = 4885|3|5|975|977|
|4886|2 × 2443 = 4886|0|2|2441|2443|
|4887|3 × 1629 = 4887|1|3|1627|1629|
|4888|2 × 2444 = 4888|0|2|2442|2444|

Python 对表中五个乘积和十个重建等式进行了精确整数检查；脚本还逐项比对实际源文件的数字与声明。**这不是 Lean 的 elaboration 或类型检查。**

主版本的库定理结论是 `¬ Nat.Prime (a * b)`，与数值目标的匹配依靠闭合自然数乘法的定义相等。该相等不会因省去 `rfl` 而被省略检查：它从一个显式证明参数转为结论类型的转换检查。候选 `CoreNumerals.lean` 和审计文件仍为五个乘积分别写出 `example : (a : Nat) * b = n := rfl`，方便原环境逐条检验。

同样，原消费者的 `his` 要求 `¬ Nat.Prime (i + 1)`；四个和分别是 4885、4886、4887、4888。审计文件逐个使用**全限定名和准确类型注解**检查这四次匹配，并重新进入原命名空间检查五个短名称。当前记录仍是候选类型匹配，不是实测通过。

## 3. 实现比较：哪些更小，哪些已知

主依据是冻结 `reference/Prime-Basic.lean`，不是用最新网上库替代固定快照。具体签名及行号见 `SOURCES.md`。

|方案|冻结位置|新证书需要什么|本轮选择|
|---|---|---|---|
|`Nat.not_prime_mul`|28–29|两个非 1 项；乘积在目标类型中归约|主实现：所给实现中源层结构最小|
|`Nat.not_prime_of_mul_eq`|31–32|一个等式项 `rfl`，加两个同样的非 1 项|保留完整可替換版本，乘积展示更直接|
|`Nat.not_prime_of_dvd_of_ne`|73–74|整除见证、因子不等于 1、因子不等于目标|后两个非等式不能与两个因子非 1 条件混同|
|`Nat.not_prime_of_dvd_of_lt`|76–77|整除见证、`2 ≤ a`、`a < n`|给出五个无 tactic 的对照项，但不是这里最省结构的方式|

主文件中每个应用含两个隐式 Nat 参数 a/b、两个证明参数；`mul_eq` 应用含 a/b/n 三个隐式 Nat 参数和三个证明参数。这里是按**源码签名**数出 4 与 6 个顶层参数，不是 Lean Expr 节点计数。在同一排版下，主文件 UTF-8 字节数为 **835**，同名 `mul_eq` 替代文件为 **885**；这也不是 `.olean` 文件大小。

库中 `not_prime_of_mul_eq` 的 body 正是 `h ▸ not_prime_mul h₁ h₂`。直接调用下层结论避免引入这一等式传输包装，但不能据此断言 checker 时间一定更短：库常量、类型归约、导入和缓存都会影响实际成本。本轮**没有测得** elaborated Expr、`.olean` 大小、编译速度或 checker 速度。

在这五个闭合小数值命题上，我选择显式指定 a/b 的 `not_prime_mul`：使用与 `mul_eq` 相同的库基础，不增加新辅助引理、不依赖 tactic 搜索，也不省略需要归约的乘积。需要显式等式形状时使用交付的 `mul_eq` 版本即可；两者实际稳定性仍待固定工具链核验。

### `mul_eq` 的无 decide 对照

```lean
example : ¬ Nat.Prime 4884 :=
  Nat.not_prime_of_mul_eq (a := 2) (b := 2442) rfl
    (Nat.succ_succ_ne_one 0) (Nat.succ_succ_ne_one 2440)
```

### 整除判据的无 decide 对照

```lean
example : ¬ Nat.Prime 4884 :=
  Nat.not_prime_of_dvd_of_lt (m := 2) (n := 4884)
    ⟨2442, rfl⟩ (Nat.le_refl 2)
    (Nat.succ_lt_succ (Nat.succ_lt_succ (Nat.zero_lt_succ 4881)))
```

这里的不等式从 `0 < 4882` 经两次 successor 得到 `2 < 4884`，不是递归证明 4884 层。`CompareCertificates.lean` 为全部五项提供相同风格，最大只叠五次 `Nat.succ_lt_succ`。整除写法本身不是错误或必然缓慢，只是在给出的显式证书中多出见证构造和序关系项，没有实测理由替代更简单的乘法方案。

## 4. 本轮真实验证与未验证

原 ZIP 的 13 个清单项、上一轮 ZIP 的 31 个清单项均通过 SHA-256 核对，两个 ZIP 的 CRC 检查正常。Python 静态程序退出 0；原消费者补丁和 R1→R2 主模块补丁分别在临时目录中由 `patch` 成功重放，生成字节与交付版本一致。

当前 PATH 中 `lean`、`lake`、`elan` 均未找到，直接版本探针无法启动。`lake env lean NonprimeCertificates.lean` 和 `lean CoreNumerals.lean` 分别产生真实 `FileNotFoundError`。两个命令都没有启动 Lean 进程，因此 Lean 退出码、耗时和峰值内存均为 `null`，不是 0 或 127。127 是辅助记录器自己的返回值。

`#print axioms`、正常项目 kernel checker、完整消费者均未运行；不写预期公理列表冒充输出。静态源码中没有禁用词，不等于已检查传递依赖。编译受阻也不构成源码被 Lean 拒绝的证据。
