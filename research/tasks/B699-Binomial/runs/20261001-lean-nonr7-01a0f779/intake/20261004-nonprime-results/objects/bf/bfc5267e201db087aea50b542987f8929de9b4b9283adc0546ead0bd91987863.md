# 精确命题和证书

**全部为静态推导；没有 Lean 接受记录。**

## 原始目标与可选 core 目标不可混写

推荐文件的命名空间是 `B699NonprimeCertificates`；直接定义文件是 `B699DefsDirect`；桥接文件是 `B699CoreBridge`。
这三个命名空间各含以下五个准确声明：

```lean
theorem not_prime_4884 : ¬ Nat.Prime 4884
theorem not_prime_4885 : ¬ Nat.Prime 4885
theorem not_prime_4886 : ¬ Nat.Prime 4886
theorem not_prime_4887 : ¬ Nat.Prime 4887
theorem not_prime_4888 : ¬ Nat.Prime 4888
```

core 文件不声明这些 Mathlib 目标，而是明确另名：

```lean
def B699CoreOnly.PrimeByDivisors (n : Nat) : Prop :=
  2 ≤ n ∧ ∀ m : Nat, m ∣ n → m = 1 ∨ m = n

theorem B699CoreOnly.not_primeByDivisors_4884 : ¬ B699CoreOnly.PrimeByDivisors 4884
theorem B699CoreOnly.not_primeByDivisors_4885 : ¬ B699CoreOnly.PrimeByDivisors 4885
theorem B699CoreOnly.not_primeByDivisors_4886 : ¬ B699CoreOnly.PrimeByDivisors 4886
theorem B699CoreOnly.not_primeByDivisors_4887 : ¬ B699CoreOnly.PrimeByDivisors 4887
theorem B699CoreOnly.not_primeByDivisors_4888 : ¬ B699CoreOnly.PrimeByDivisors 4888
```

这些展示性签名省略证明正文，不是本包的编译输入；完整可选源码均含显式证明正文，无占位。

## 五组精确真因子义务

以下每行列出完整义务 `d ∣ n ∧ 2 ≤ d ∧ d < n` 的分量。
`Nat.le_add_right x y` 的原类型是 `x ≤ x + y`。

| n | d,k | 整除见证；其等式类型 | `2 ≤ d` 的证据 | `d < n` 的证据 |
|---:|---|---|---|---|
|4884|2,2442|`⟨2442, rfl⟩`；`4884 = 2 * 2442`|`Nat.le_refl 2`|`Nat.le_add_right 3 4881`|
|4885|5,977|`⟨977, rfl⟩`；`4885 = 5 * 977`|`Nat.le_add_right 2 3`|`Nat.le_add_right 6 4879`|
|4886|2,2443|`⟨2443, rfl⟩`；`4886 = 2 * 2443`|`Nat.le_refl 2`|`Nat.le_add_right 3 4883`|
|4887|3,1629|`⟨1629, rfl⟩`；`4887 = 3 * 1629`|`Nat.le_add_right 2 1`|`Nat.le_add_right 4 4883`|
|4888|2,2444|`⟨2444, rfl⟩`；`4888 = 2 * 2444`|`Nat.le_refl 2`|`Nat.le_add_right 3 4885`|

例如第一条上界证据原本是 `3 ≤ 3 + 4881`；闭合加法归约后是 `3 ≤ 4884`，与 `2 < 4884` 定义相等。
具体接缝已写入 `AuditCoreOnly.lean`，目前没有实际运行。

用于析取矛盾的非等式：

|n|`d ≠ 1`|`d ≠ n`|
|---:|---|---|
|4884|`Nat.succ_succ_ne_one 0`|`Nat.ne_of_lt (Nat.le_add_right 3 4881)`|
|4885|`Nat.succ_succ_ne_one 3`|`Nat.ne_of_lt (Nat.le_add_right 6 4879)`|
|4886|`Nat.succ_succ_ne_one 0`|`Nat.ne_of_lt (Nat.le_add_right 3 4883)`|
|4887|`Nat.succ_succ_ne_one 1`|`Nat.ne_of_lt (Nat.le_add_right 4 4883)`|
|4888|`Nat.succ_succ_ne_one 0`|`Nat.ne_of_lt (Nat.le_add_right 3 4885)`|

这里没有完整素性判定，没有证明 d 或 k 为素数，也没有展开一长串后继界证明。
大偏移作为 `Nat.le_add_right` 的数字参数，并不等于当前证明正文包含同样数量的递归步骤；实际 elaboration/kernel 成本仍未测量。

## core 析取消去

对另名谓词，设 `h : PrimeByDivisors n`。利用真正的合取定义，有：

```lean
h.2 d ⟨k, rfl⟩ : d = 1 ∨ d = n
```

`Or.elim` 把两个分支分别交给 `d ≠ 1`、`d ≠ n`，得到 `False`。
这一 `.2` 用法只用于另名合取；没有把 `h : Nat.Prime n` 当成同样的合取。

## 原始 Nat.Prime 的直接定义路线

固定定义 `Nat.Prime n := Irreducible n`。
对 `h : Nat.Prime n`，固定结构字段提供：

```lean
h.isUnit_or_isUnit (a := d) (b := k) rfl : IsUnit d ∨ IsUnit k
```

两个分支各经 `Nat.isUnit_iff.mp` 得到 `d = 1` 或 `k = 1`，再与显式非 1 证书矛盾。
这一路径不使用 `Nat.prime_def` 或任何非素性库定理；它依赖 Mathlib 的实际定义、单位接口和相应实例，所以不是 core-only。

五条的非单位证据均具有以下精确结构：

```lean
fun u => Nat.succ_succ_ne_one (d - 2) (Nat.isUnit_iff.mp u)
fun u => Nat.succ_succ_ne_one (k - 2) (Nat.isUnit_iff.mp u)
```

实际源码使用闭合参数而不是运行减法：

|n|d-2|k-2|
|---:|---:|---:|
|4884|0|2440|
|4885|3|975|
|4886|0|2441|
|4887|1|1627|
|4888|0|2442|

## 桥接回原命题

`Nat.prime_def` 提供 `Nat.Prime n ↔ B699CoreOnly.PrimeByDivisors n`；后者仅在自定义谓词处做定义展开。
每个桥接的正文为：

```lean
fun h => B699CoreOnly.not_primeByDivisors_4884 (Nat.prime_def.mp h)
```

其余四项更换对应数值。这里使用的是有证明的 `Iff.mp`，不是 `Iff.rfl` 将原 `Nat.Prime` 强行改写为合取。

## 推荐乘积路线

`Nat.not_prime_mul (a := d) (b := k)` 的结论是 `¬ Nat.Prime (d * k)`。
五个乘积归约为对应 n，因此只需要两个非 1 证据；没有显式搬运等式。
上轮 `Nat.not_prime_of_mul_eq ... rfl` 同样是合理候选，不因本轮删去包装而被宣称错误或更慢。
