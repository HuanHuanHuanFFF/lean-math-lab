# 仅用现有工具链复现，不安装、不改仓库

## 入口条件

必须已经有原项目固定 v4.33.1 native Lean executable、锁定 manifest 对应的依赖及可导入对象。附件的 lean-toolchain / manifest 不是完整环境。缺任一项就停止，不执行 elan/lake 安装、lake update、cache get 或依赖构建。

本包提供的 replay_existing.py **不调用 lake/elan**，只调用显式传入的已有 native Lean、只读 git rev-parse 和标准 Python。它在新建外部目录写文件，不往项目内放源码/olean。

```sh
python3 repro/replay_existing.py   --lean /EXISTING/leanprover--lean4---v4.33.1/bin/lean   --project /EXISTING/lean-math-lab   --out /NEW/OUTSIDE-REPOSITORY/b699-r3-check
```

替换这三个路径为确实存在的工具/项目和新的输出位置；不是建议创建或下载工具链。脚本拒绝已存在输出目录、项目内输出、交付目录内输出，以及明显的 installer/shim。实际 ELF/Mach-O/PE 工具身份仍应由执行者确认。

读取并记录：实际 lean --version、工具二进制 SHA-256、原项目 lean-toolchain、九项固定依赖 rev 与 checkout HEAD、mathlib Basic 源码 LF hash、已加载 Basic.olean hash。Git HEAD / 单一对象哈希不等于整个依赖对象闭包已重建认证；依赖缓存仍是预先存在的输入。完整正常 checker 验收仍是后续门。

## 最小命令与对象生成

已配置固定依赖的独立环境中，原约定最小源码检查命令是：

```sh
lake env lean NonprimeCertificates.lean
```

本轮实际尝试止于 lake 不存在。不要在会触发自动下载/安装的环境运行它。

实际重放脚本使用下面等价的直接 native 调用形式。这里 LEAN 为已有 binary，OUT 为新建外部目录，LEAN_PATH 由已存在依赖构建目录构造，并以 OUT 为第一项。

```sh
"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$OUT" -o "$OUT/NonprimeCertificates.olean" "$OUT/NonprimeCertificates.lean"

"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$OUT" -o "$OUT/TypeAudit.olean" "$OUT/TypeAudit.lean"

"$LEAN" -j1 -DautoImplicit=false -DrelaxedAutoImplicit=false -DElab.async=false   -R "$OUT" -o "$OUT/AxiomAudit.olean" "$OUT/AxiomAudit.lean"
```

这不是 checker 命令。脚本还先运行 ImportOnly 和 CoreNumerals 定位导入/核心问题。每条前序命令必须启动并退出 0，才进入下一条；不允许主编译失败后继续用旧 olean 审计。不给 maxRecDepth/maxHeartbeats 调大值。源码级 TypeAudit 的严格选项不能替代主文件编译命令的严格选项。

## 验收文件要求

CoreNumerals 中 5 个乘积用 Eq.refl 检查，10 个非 1 条件用准确 Nat 类型注解检查。TypeAudit 中 25 个数值/类型 example、5 个短名 example、4 个 successor example、4 个证书对 example 分别检查关键转换和导入后的可见性；这些 example 不是原大型 consumer 证明。

AxiomAudit 必须保留全部 stdout/stderr，获得两个库引理与五个新声明的实际输出。必须检查 sorryAx、新增非预期 axiom/信任入口；标准库依赖与本项目新增公理分开记录，不预填空列表、不预设恰好三个标准公理。脚本未发现几个明显坏名称也仍需人工审查全部输出。

## 耗时与缓存

record_command 记录实际子进程总墙钟时间，包含进程启动与 import 成本；本脚本不采集峰值内存，故写 null。ImportOnly 仅辅助说明启动/import量级，不能简单相减当精确证明项成本。依赖 cache 预先存在；没有清缓存、重新编译依赖或认证缓存来源。报告源/对象哈希、命令与退出码，旧失败 2.188 秒不能当成功对照。

## 正常 kernel checker

准确项目 checker 入口没有给出，本包不猜命令，脚本中 checker_command=null。原执行者在小模块检查完成后使用原项目正常入口，另存其真实命令、原始输出、退出码、源/对象哈希、耗时及可得内存。该门未通过前，只报告编译/类型检查状态，不宣称完整验收。
