# 有限证书格式与声音性义务

## 不由JSON证明的输入

输入采用BFT Theorem2.1及原三窗口通用命题。消费者证明详见 PROOFS.md。程序重算高度整数比较，但不证明BFT，不以源JSON的PASS字段作假设。

## 通用字段

七项schema `b699-symbolic-crt-contraction-v1`：

- `target_indices`必须恰等于17,23,26,27,30,32,33，profiles恰好每项一次。
- 每项 `i,r,s,height_bits` 确定t,λ,E,K。checker由小素数筛及Legendre公式重新构造。
- `prime_witnesses`严格递增且无重复，每个数完整试除至isqrt。每个素数必须在末端数据实际使用。
- 大整数用JSON十进制字符串，以免其他语言转成浮点。所有数学判断必须继续用整数。

## 每个符号阶段

`bound_stages`各行包含H,M,start,next_H、小素数幂族数、不同颜色幂对数、非空CRT族数、带重数的进程项数，以及一个达到最大值的见证。

checker不相信这些计数：独立生成完整p幂族和位移d，改解另一余因子模Q，重新计算全部整数区间。开始H=2^height_bits，每步next_H供下步使用。中间步骤严格下降，最后一次同高只表示所选覆盖法达到固定点。

最大值见证可用于排查端点错误；全域上界来自全部CRT族的完整遍历，不来自一份单独达到见证。即使达到见证合法，也不代表原题noCommon。

## 显式末端

`terminal_cover`保存M证书、每个p,h的完整余因子范围、原始短区间数量和至少双色的规范化区间并。checker按A优先独立重建每色并，对每对不同p取交集，最后取并。

`candidate_intervals`必须恰等于末端双色并加全部低端 `[2i+2,start−1]`。范围不能仅从n≥2^22开始，因为初始高度证明已将更小n包含在反例域。

末端两类见证：

- `top_prime_intervals:[a,b,p]`：检查a≥2i+2，p≤a≤b<p+i，并在完整试除的素数表内。
- `large_divisor_rows:[n,d]`：检查d>0、i!d|(n)_i、gcd(d,(i−1)!)=1、Kd^λ>n^E。

见证区间/单行的并必须恰等于候选并，各类计数之和等于候选总数，避免重叠计数掩盖遗漏。

## 可优先采用的三项证书

schema `b699-two-colour-contraction-v1`只处理27,30,33。每个阶段直接使用显式末端型数据，没有CRT层。最终高度与完整七项的对应部分相同，并由 `compare_paths.py` 逐字段检查。

这三项有限证书可先采用，但它们的初始全量词高度仍含BFT纸面依赖；不能单靠Python检查就叫Lean全域验收。

## 准备形式化时的分层

建议独立实现四个消费者：

1. 原始noCommon与H/M不等式到完整双色表示，含n≤M分支。
2. 给定素数幂族及余因子范围，CRT区间包涵每个实际解；需要有符号整数floor/ceil。
3. 有限族覆盖以及最大端点到新严格高度。
4. 顶端素数与大整数除子到原始Common结论。

算法完整性定理和证书数据的执行成本是不同工作；本轮未开展Lean或成本估计，不保证普通Python约一分钟的计算也能由内核相同速度完成。
