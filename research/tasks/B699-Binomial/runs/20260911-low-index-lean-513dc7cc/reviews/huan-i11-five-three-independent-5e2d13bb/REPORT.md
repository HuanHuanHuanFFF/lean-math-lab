# i11 的 (5,3) 边：独立数学与陈述复核

结论：在本次读取的源码版本中，未发现阻断性数学错误。固定参数、共同 m、两条 δ 行、7/2 缩放、实际 G 与 Hom 余项、严格指数抽取、数值率和边结论相互一致。这个结论是只读复核，不是新增 Lean 验收。

“四个增长树仍缺”只适用于 `five_three_edge_of_growth_trees` 这个固定参数的**余因子边**：它的其他特殊数值参数已在证明文本中消去。接到原题的实际素数幂组件，还需调用现成窗口转换并补 ceil 窗口/高度包装。完整 i11 仍需其余四条边、全局乘积与尾部消费者，以及随后完整有限消去。

本轮没有改候选、已验库或 Git，也没有运行 Lean。源码和验收证据的准确 SHA、读取时间见 `SOURCE_MAP.json`；小范围独立精确诊断见 `exact-checks.json`。

## 2. 同一 m 和严格指数界

`I11Edge/FiveThree.lean:13–43` 定义唯一的

```
m(Y) = min {m : Nat | 4Y < Z^m}.
```

两端分别取 Jp=5²⁰⁰⁰⁰、Jq=3³⁵⁰⁰⁰，但调用的是同一个 `fiveThreeIndex Y`。M=213 是统一下界，不是把所有 Y 的 m 固定为 213。`LeastExponent` 同时保留选中阈值与前一指数上界 `Z^(m-1)≤4Y`；容量证明没有只靠一个过大的 Bernoulli 存在性见证。

`I11Numeric/Selector.lean:12–46` 给出前一指数证书及两端各三条容量证书。六个大幂不直接展开，来自精确短幂：5⁵¹²≤2¹¹⁸⁹，3¹²⁸≤2²⁰³，2²⁸⁹≤Z⁴，Z⁸≤2⁵⁷⁹。所有容量余量分别为 1000−354=646、1000−228=772，与最终边权重一致。

`Capacity.small_cofactor_forces_exponent` 的逻辑是：若 A¹⁰⁰⁰<Y³⁵⁴ 且 Y≤5^e A，但 e≤20m，则容量给出 `(5^e A)^1000<Y^1000`，与窗口下界矛盾。因此得到的是 **20m<e**，不是只有 ≤。3 端同理得到 **35m<f**。`SelectedEdge:37–43` 的严格小余因子前提来自两个非严格边结论的失败，严格性正确；`ActualGap` 只需 ≤ 来恢复幂乘积，使用 `<` 的弱化没有损失。

## 3. 两条 δ 行与分别清分母

`rowDelta true=0`，`rowDelta false=1`。同一个 m 对应

- δ=0：u=3m，v=2m−1；
- δ=1：u=3m−1，v=2m。

两行都满足 u+v+1=5m。m≥213 因而覆盖所有 Nat 下标守卫及两行的实际 G 阈值 129（单独 δ=1 已在 m≥21 成立）。没有为两行另选 m，也没有把一行的 G 借给另一行。

记 P̂δ、Q̂δ 为实际 `pNormalizedValue`、`qNormalizedValue`，记 Gδ=`qContent u v u`。这个 Gδ 是 `gcd_{0≤h≤u}(choose(2u-h,u)*choose(v+h,h))`，不是假设的高度函数或形式上的内容占位符。P、Q 的系数分别除以该行 Gδ，其整除性来自已验 Pade/Content；两行行列式非零来自已验实际构造。

`ActualBounds:35–51` 的两个实际等式是

```
Gδ * Q̂δ = 4375^u * actualQ(5,3,δ,m,1/4375)
Gδ * (4375^(5m)*P̂δ − 4374^(5m)*Q̂δ)
    = 4375^v * actualE(5,3,δ,m,1/4375).
```

这正是 `HomRemainder.normalized_integer_error_cast_q` 的 x=1,y=4375 代入。x 的 (2u+1) 次幂为 1；余下 y 次数是 **v**，不是 u 或 5m。Q 与余项分别用 u≤3m、v≤2m 放宽，这也是 δ 依赖消失的准确位置。

## 4. 7/2 缩放、带符号窗口差及矛盾预算

令 U=5^(e−20m)A，V=3^(f−35m)C。原窗口差为 `5^e A−3^f C`，可以为正、负或 0。`ActualGap:16–28` 只要求其绝对值≤24，没有固定符号或非零差的前提。

种子系数分别取 a=7^(5m)、b=2^(5m)，被选中的非零整数线性形式是

```
2^(5m) Q̂δ U − 7^(5m) P̂δ V.
```

误差项则为

```
625^(5m)·7^(5m)P̂δ − 2187^(5m)·2^(5m)Q̂δ
=4375^(5m)P̂δ−4374^(5m)Q̂δ.
```

因此 7 和 2 的清分母因子各归其位，没有把 7/2 一次错误地提到两行之外。实际行列式的输入 x=1、y=4375 都非零；V≠0 由 C≥1 保证。A>0 虽未作为最终边单列，但由巨大 Y 的窗口下界自动成立。δ 的选取是在实际两行中由整数桥给出，大小界对两个 Bool 都有效。

设 BQ=βλQ、BE=βλE，g=Lt³。`ScaledGap` 使用

```
qRate = 625^5*g / (2^5*4375^3*BQ)
wRate = (625*2187)^5*g / (4375^2*BE).
```

精确有理检查确认 qRate=原 Ω3^d，wRate=2187^5·原 Ω4^d，Z=floor(wRate)。这里种子差 D0=1 与窗口粗差预算 24 是不同量；48=2·24 是把两个误差项分别压到下界一半所需的常数。原 i11 窗口宽度只有 10，放宽为 24 合法。

qRate^m>48 使 Q 项的两倍严格小于 625^(5m)。另一项用 `2187^(5m)V=Nq`、Nq≤2Y，以及 `4Y<Z^m≤wRate^m`，得到 2Nq<wRate^m，故余项的两倍也严格小于同一下界。两项相加严格小于整数桥给出的 ≥ 下界，矛盾。所有取严格不等式的位置都有明确来源；不依赖 G 下界的额外严格余量。

## 5. “只剩四树”的准确范围

`ActualNumeric.five_three_edge_of_growth_trees` 的特殊数据参数确实仅为

```
qt : ∀ row : Bool, GrowthTree λQ (qWeight 5 3 δ z) (qCore 5 3 z)
et : ∀ row : Bool, GrowthTree λE (eWeight 5 3 δ z) (eCore 5 3 z)
```

即 Q0、Q1、E0、E1 四个有限证明对象。它们是实际局部 Bernstein 锥与二分覆盖组成的 `GrowthTree`，不是把所求全 m 增长结论直接作为字段。实际阶乘 (5,3) 全 m 界、m=1 初始常数、G、Hom、行列式和八个数值证书都在证明文本中经具体库调用消去。

不过该声明仍保留普通窗口前提：Y≥Y0、C≥1、两个窗口≥Y、3 端窗口≤2Y、绝对差≤24。并且本次现有验收快照只直接确认 I11Numeric/Basis、RatioPower；尚未在对应 receipts 中发现整个 I11Edge/I11Scaled/Selector/ActualNumeric 链的成功验收。因此“四树是源码陈述中剩余的特殊数据”不等于“无条件实际边已 Lean 验收”。

## 6. 原组件边的准确落点

必须区分三个层次的字母：种子系数 a=7,b=2；窗口偏移 σ5、σ3∈[0,10]；窗口余因子 A、C。图中的顶点值则是

```
X5 = primeComponent n 5 = 5^((n.choose 11).factorization 5)
X3 = primeComponent n 3 = 3^((n.choose 11).factorization 3).
```

最终需要的是

```
X5^1000 * Y^354 ≤ n^1000
OR X3^1000 * Y^228 ≤ n^1000.
```

当前余因子边结论是 `Y^354≤A^1000 OR Y^228≤C^1000`。这两个结论不相同，但已验 `I11SmallPrimes/Window.lean:58–64` 的 `primeWindow_graph_capacity` 正好完成转换，因为 A·X5=n−σ5≤n、C·X3=n−σ3≤n。反过来，任一组件边失败都通过这个已有蕴含得到对应余因子边失败，进而给出严格小余因子前提。无需重新证明组件与余因子的乘积结构，更无需假设余因子 p-free。

`primeWindow_nonempty` 包含 e=0 或 f=0 的情况；这些情况会直接落入较大的余因子边，不能预先全局删除。两个窗口偏移可以相同，给出差 0；证明仍然成立。

## 7. Y=ceil(n/2) 的剩余包装义务

取自然数 `Y=(n+1)/2`。从原窗口同时得到所需条件还应明确写出下列桥：

1. n≥20、σ≤10 ⇒ Y≤n−σ≤n≤2Y。
2. n≥2¹⁵³⁶⁰ ⇒ Y≥2¹⁵³⁵⁹（保持边界等号）。
3. σ5,σ3≤10 ⇒ `|(n−σ5:Int)−(n−σ3:Int)|≤10≤24`。
4. 取 `e=(n.choose 11).factorization 5`、`f=...3`，由两个 `PrimeWindow.equation` 和交换乘法接入 ActualNumeric，再对其 OR 两支调用 `primeWindow_graph_capacity`。

这些桥没有新的数学障碍，但在指定三组模块内没有现成包装定理。n≥11 本身不足以给出第 1 项：n=19,σ=10 时 Y=10 而窗口为 9。原尾部 n≥2¹⁵³⁶⁰ 则充分；不能只把 Y≥Y0 与窗口下界当作未解释的外部前提。推荐下一项独立小证明就是这个实际窗口组件包装，参数只保留四树，不保留额外窗口或“组件分解”假设。

该实际边可以在所有 n≥2¹⁵³⁶⁰ 下陈述，不必另用合法 j 或 noCommon；这些条件属于后续五边乘积和原题反例消费者。
