# 三个 Pro 共用执行约定

此文说明执行与证据边界，不规定数学路线；具体研究目标以对应A/B/C提示词为准。

1. 使用本包冻结材料直接开工。仓库仅作只读补充：https://github.com/HuanHuanHuanFFF/lean-math-lab ，固定参考提交9d4228e3ed0de4bb6b8e555ca59af3f53d578c67。无须等待PR、huan或其他Pro本轮结果；无法访问仓库时使用本包，并如实说明。
2. 在新的工作目录保存本轮成果，保留输入与历史失败原件。旧包中的TASKS、提示词、时间预算、等待合并要求属于历史材料，本轮任务由用户当前消息和本包prompts定义。检索按需进行，采用外部定理时核对原始来源、准确量词、有效阈值和适用范围。
3. 实际研究并迭代。不设人为总时限；取得进展保存检查点后继续，发现路线受阻则说明原因并换有依据的方向。目标完成、用户停止或平台实际中断时交接；合理尝试后确实无法推进时准确交代障碍，不声称会话结束后仍在后台研究。
4. 全域结论覆盖原题全部量词。保留p=i、完整素数幂和noCommon前提；若选择其他证明对象，明确它与原题的逻辑关系。条件接口、无界子区域、非有效有限性、明确有效高度、完整闭合分别登记；“可行模型／未覆盖点”与“原题反例”分别论证。
5. 有限计算采用精确、可重跑的检查，说明候选完备性与所有分支覆盖；依据实际验证需要复用或重跑材料。数值探索和Python PASS不等于无限推导、Lean内核验收或独立人审。研究会话交付自己的检查结果，不冒充另一个核验任务。
6. 输出控制按实际环境执行：先看目录和报告，按需读取大型数据；默认一次工具输出约12KiB以内，完整日志写文件。ZIP通过附件传输，绝不转Base64或把完整JSON/压缩包分块灌入聊天。内存重计算先串行，按实测资源调整；不预设VPS、huan和网页沙箱相同。
7. 交付中文REPORT、HANDOFF、完整推导、采用来源、实际检查与失败记录，并给可下载证据包。保留复现命令与证据等级；数据可精简重复拷贝，但必须留下完整可恢复来源。本轮不负责huan的Lean任务，也不向main写入或替用户合并PR。
